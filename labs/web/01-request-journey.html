② 12 个阶段的说明

1
URL 解析 → DNS 查询
把 127.0.0.1 或域名换成 IP 地址。域名要走 DNS，本机地址直接用。
2
TCP 三次握手
浏览器与服务器建立可靠连接：SYN → SYN+ACK → ACK。这一步有网络往返开销，所以需要连接复用（Keep-Alive）。
3
构造 HTTP 请求报文
请求行 + 请求头 + 请求体。看 DevTools 的 Network 面板能看到原文。
GET /api/books?page=1&size=3 HTTP/1.1 Host: 127.0.0.1:8080 Accept: application/json Origin: http://localhost:5173
4
服务端接收 → Tomcat → Filter 链
Tomcat 解析报文成 HttpServletRequest。Filter 在这一层（编码、CORS、日志追踪 ID）。CORS 预检（OPTIONS）也在这一层被处理。
5
DispatcherServlet 路由匹配
Spring MVC 根据路径找 Controller 方法，同时执行 Interceptor 的 preHandle（鉴权、限流）。
@GetMapping("/api/books") public R<PageResult<BookVO>> list(@Valid BookQueryDTO query)
6
参数绑定 + 校验
把 ?page=1&size=3 绑定到 DTO 的 setter，然后执行 @Valid 校验。失败 → 400 + 字段级错误。
7
Controller → Service（IOC 注入）
Controller 不 new Service，是容器在启动时通过构造器注入的。这就是 IOC/DI 的实际作用。
8
Service 业务逻辑
白名单校验排序字段（防 ${} 注入）→ 查总数 → 查当前页 → 批量取分类名（避免 N+1）→ 组装 VO。
9
Mapper → MyBatis → SQL
MyBatis 把接口方法翻译成 SQL，用 #{(预编译)} 传参，结果集按驼峰规则映射成 Entity。这一步连的是真 MySQL。
SELECT id, title, author, price, stock FROM book <where> ... </where> ORDER BY id desc LIMIT ? OFFSET ?
10
MySQL 执行 → 返回结果集
InnoDB 走索引（或全表扫），MVCC 保证读取一致性，返回行数据。
11
响应序列化 + 统一包装
Service 返回 R<PageResult<BookVO>>，Jackson 序列化成 JSON，加上 CORS 响应头。
{"code":0,"message":"ok","data":{"list":[...],"total":12},"timestamp":...}
12
浏览器接收 → JS 渲染
Ajax 拿到 JSON（不刷新页面）→ 判断 code === 0 → 更新 DOM（原生）或改响应式数据（Vue）。
